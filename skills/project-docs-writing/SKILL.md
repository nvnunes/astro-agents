# Project Docs Writing

Use this skill for human-facing project documentation.

Pair with `$technical-writing` for common prose discipline, then read `references/project-docs.md` for project-doc role, source-of-truth, and organization rules.

Write docs so humans can find the current owner of a fact quickly. Keep durable facts in the strongest local source of truth, avoid duplicate instructions, and link rather than restating when another document owns the detail.

For README-specific work, switch to `$readme-writing` as the primary skill. Use this skill only as an additional lens when the README needs source-of-truth or documentation-surface judgment.
