# Record Existing Entry Instructions

Use this file when continuing or revising an existing entry.

`Record Existing` updates one existing entry document without changing unrelated entry content.

## Procedure

1. Resolve the target entry from the entry ID, path, topic, date, chat context, log summary, entry folder names, search results, or existing links before editing.
2. If the reference matches multiple entries, ask before editing.
3. Append to an existing section when it clearly fits; otherwise create a new descriptive `##` section.
4. Apply `skills/research-logging/references/operation-record-content.md` for shared content guidance.

## Edge Cases

Suggest splitting only when distinct topics impair retrieval or maintenance
under `skills/research-logging/references/file-entry.md`; length alone is not a
reason. Use `skills/research-logging/references/file-entry-naming.md` and wait
for researcher approval before changing document boundaries.

When an updated experiment replaces work the researcher does not intend to
retain, remove its prose, artifacts, and scripts rather than keeping a
historical or provisional incarnation. Keep only rejected evidence needed by a
retained result, decision, or lesson. Before deletion, identify the exact
cleanup boundary, copy the material to a recoverable temporary location outside
the log, and obtain researcher approval. Delete only after approval.

When researcher-provided state resolves a TODO or provisional marker, replace
or remove that marker in the affected section. Do not infer that validation,
approval, or another pending action occurred.

If added or revised content makes the descriptive topic slug inaccurate, suggest renaming the entry folder and updating affected links using `skills/research-logging/references/file-entry-naming.md`.
