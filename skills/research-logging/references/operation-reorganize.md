# Reorganize Operation Instructions

Use this operation only when the researcher explicitly asks to reorganize a
research log or approves a specific Reorganize recommendation from Review.
Reorganize changes structure without changing research meaning. A Review
recommendation alone does not authorize edits.

## Resolve The Change

- Resolve one maintained log and the exact source and destination documents,
  sections, or paths. If more than one entry could match, ask before editing.
- Preserve every stable entry ID. Read `references/file-entry-naming.md` only
  when an entry folder or document name changes. Read
  `references/file-entry.md` only when document placement or boundaries change.
- Treat the researcher's named structural change as the authorized boundary.
  Obtain approval before adding an unrequested document boundary or deleting a
  research-log file.
- Do not infer Reorganize from Continue, entry length, multiple topics, or an
  imperfect folder slug.

## Apply The Change

Use normal workspace editing tools. Reorganize has no CLI operation.

- Preserve prose, research meaning, entry IDs, evidence IDs, and the set of
  presented results. Move content intact unless the request also authorizes a
  rewrite.
- Update only references affected by changed paths or anchors, including
  summary entry links, local document links, citations, recorded commands,
  evidence-record document paths, and presentation-marker associations.
- Move entry-owned support material only when the requested organization
  requires it. Load only the corresponding file guidance for an affected
  command, input, retention decision, evidence presentation, or document.
- Preserve the summary's fixed validation-report link and every generated
  validation file exactly.

Use these workflows for common same-entry changes:

- **Rename:** Rename the requested entry folder or document, or revise a
  heading, then update every affected path, link, anchor, command, and evidence
  document reference. Keep the entry and evidence IDs stable.
- **Move a section:** Move the complete section between documents in the same
  entry. Update links and anchors, and change `document` only for evidence
  records presented by that section.
- **Split documents:** After approval, keep the same entry folder and entry ID,
  create the approved suffixed documents, and distribute complete sections
  between them. Keep shared support material at the entry root unless the
  researcher approved a narrower location. Update summary and local links and
  affected evidence document paths.
- **Merge documents:** After approval, move complete sections into the chosen
  surviving document, update affected links and evidence document paths, and
  delete the empty source document last.

## Boundaries And Completion

- If the structural change would remove active experimental content or its
  owned material as superseded work, stop and request explicit Replace
  authorization. Do not load or apply Replace from the Reorganize request.
- Do not revise current understanding or summary `## Follow-ups` without a
  separately authorized Update Summary operation.
- Check only changed paths, links, anchors, commands, markers, evidence records,
  and support references. Leave unrelated log material and generated validation
  state unchanged.

Report the completed structural changes, any approved deletions, and any
remaining ambiguity or separately authorized operation still required.
