# Reorganize Operation Instructions

Use this operation only when the researcher explicitly asks to reorganize one
maintained research log or approves a specific Reorganize recommendation from
Review. Reorganize changes structure without changing research meaning. A
recommendation, validation finding, long entry, or imperfect slug does not
authorize it.

## Select One Workflow

Resolve the exact authorized change and read exactly one focused reference:

- Entry date, slug, title, or ordering; complete-log relocation; a no-move
  evidence, data, or retention identifier rename; or removal of an already
  empty entry: read `references/operation-reorganize-identity.md`.
- Moving sections within one stable entry, including creating, splitting, or
  merging its documents: read
  `references/operation-reorganize-documents.md`.
- Moving a section between stable entries, splitting one stable entry into two,
  or merging stable entries: read
  `references/operation-reorganize-transfer.md`.

If the request spans workflow families, apply each relevant focused procedure
in dependency order, but do not load an unrelated family. Ask before editing
when the intended boundary, destination, record selection, or support-material
ownership is ambiguous.

## Boundaries

- The agent owns semantic partitioning, all Markdown and link edits, selected
  support-file movement, and the records named for transfer. The CLI owns only
  verified closed identities and coordinated authored-registry changes.
- Preserve prose, research meaning, presented results, and stable identifiers
  unless the requested workflow explicitly authorizes an identity change.
- Never edit a registry directly, rewrite generated validation, infer a record
  set, move an entry between logs, or use Reorganize to correct malformed state.
- If the change would remove active experimental work or owned material as
  superseded, stop and request separate Replace authorization. Do not load
  Replace merely to finish Reorganize.
- Do not revise current understanding or summary follow-ups without separately
  authorized Update Summary work.

Report the structural outcome, any required producer reruns, and any ambiguity
or separately authorized operation still outstanding.
