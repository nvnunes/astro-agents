# Summary Check Operation Instructions

Use this file when reviewing `<theme>.md` against the theme index and entries.

This operation is report-first and does not edit files unless the user approves fixes.

Do not make automatic edits during `Check`. Formatting corrections, heading changes, link fixes, numbering/list changes, style cleanup, and summary prose improvements are still fixes. Report them first and ask before applying them.

When evaluating or fixing summary prose, apply `skills/research-logging/references/file-summary.md`, including its `skills/project-docs-writing/references/project-docs.md` style boundary. Treat verbosity, convoluted writing, and entry-detail dumping as summary-quality issues when they reduce scanability.

## Procedure

1. Confirm the requested check scope when broad or ambiguous.
2. Review `<theme>/index.md` first, including `## Concepts` and entry cards. If the user says `entities`, treat that as the relevant concepts, concept sections, index cards, or entry-routing entities unless they define another meaning.
3. Review `<theme>.md` for current claims, structure, links, open questions, decisions, and follow-up.
4. Use the index to select relevant entries before loading evidence.
5. Scan entry `##` headings before opening full entries when entries are large.
6. Escalate to broader entry review only when the index is incomplete, stale, contradictory, or when the user explicitly asks for a broad review.
7. Check that major summary claims can be navigated back to supporting entries through clickable entry-ID links.
8. Report unsupported claims, stale claims, missing important evidence, weak or broken entry links, and summary/log mismatches.
9. For each inconsistency, propose a resolution direction: update the summary from the entry, update the entry from human-approved direction, or preserve the disagreement as an explicit question or follow-up.
10. Ask before applying fixes.
11. If fixes are approved, apply summary-side fixes as targeted summary updates using `skills/research-logging/references/operation-summary-update.md`.
12. If entry-side fixes are approved, update the affected entry through the relevant capture/editing guidance and preserve source wording unless the human explicitly approves rewriting.
13. Update `<theme>/index.md` only if approved fixes change how entries should be routed, interpreted, or described.
14. Report evidence gaps, contradictions, and follow-up created by the check. Record them only if the user approves fixes or capture work.

## Files To Consult

- For `<theme>.md` structure, read `skills/research-logging/references/file-summary.md`.
- For index routing or affected concepts, read `skills/research-logging/references/file-index.md`.
- For dated entry interpretation, read `skills/research-logging/references/file-entry.md`.

## Completion

Report findings as concise narration.

Include:

- unsupported or stale summary claims
- missing important evidence
- weak or broken entry links
- summary/log mismatches
- proposed resolution direction for each inconsistency
- follow-up created by the check

If there are no findings, say that explicitly and note any residual gaps in the review scope.
